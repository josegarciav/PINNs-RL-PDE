    What has been built¶

    The record of every release: what each one set out to do, what was built, and what the experiments it served found. Newest first. The terse per-release list of changes is the changelog; what comes next is the roadmap. Experiment codes (B01, J06, ...) name folders under experiments/, each with a README stating the question, the protocol and the result.

    Unreleased: v0.9 so far¶

    The engine release. The compiled kernel became the default, a benchmark against every alternative showed where it was behind, and the two mechanisms that benchmark named were built into the package. The terse list is in the changelog; what is still open is on the roadmap.

    • A head-to-head with the alternatives (I17). Done: the same step in eager PyTorch, torch.compile, torch.func, JAX (reverse, forward and Taylor mode) and DeepXDE on nine equations (Benchmarks). The first run had JAX's forward mode 1.2–1.3× ahead of the kernel and named why (fused per-equation loops, a rational tanh); with both built in, pinnrl is first on all nine on an Apple M4 (1.1–1.8× JAX, 2.4–7.7× eager PyTorch, 2.7–9.9× DeepXDE, about 3× PhysicsNeMo where that runs). On a Linux x86 runner JAX's forward mode is 1–11 % ahead on seven plain-network problems; pinnrl leads at fourth order and with layer normalization.
    • derivatives="auto" as the default. Done: the kernel wherever it applies, autograd elsewhere, silently. A gradient of the kernel that is differentiated again (analysis.spectrum, analysis.surrogate, any Hessian-vector product) is taken by autograd on the same function, and torch.func transforms see the ordinary module, so no tool has to know which engine ran.
    • A step compiled per equation. Done: pinnrl.native.specialize writes C++ for the equations given as text (the Taylor recurrences through tanh as one fused loop for exactly the streams they use, the residual and its adjoint inlined by SymPy), compiles it once and caches it; the general kernel serves the first 32 evaluations, so a short run never waits. 1.3–1.7× over the general kernel on an Apple M4, 1.1× on Linux x86, where the matrix products dominate.
    • The compiled step for the inverse problems, scaled networks and layer normalization. Done: the step returns the gradients of trainable parameters, takes measured inputs and unknown functions of the coordinates as per-point values with their adjoints returned, handles a network's input and output scaling (normalize=True), and runs layer normalization through generated row loops of its own, 1.3–1.4× the general kernel with normalization on. Each case is checked against autograd in tests/unit_tests/test_native_specialize.py.
    • A faster tanh in the kernels. Done: a rational approximation (the form Eigen uses) in place of Accelerate's vvtanhf and the Cephes form on Linux, 0.4 against 1.1 ns an element at float32 accuracy (2.4e-7).
    • A manual benchmark workflow. Done: .github/workflows/benchmark.yml runs experiment I17 on a Linux x86 runner, started by hand.

    v0.8: performance and the PINN's case (released 2026-11-18)¶

    • Time breakdown of a step, and the same step in C++ and Rust (I01, I11). Done: the step is arithmetic (sampling, optimizer and bookkeeping under a tenth); tanh and the double-backward passes dominate; a framework-free step on Accelerate takes 3.6 ms in either language against 8.8 ms in PyTorch and 10.6 ms in the trainer.
    • The kernel in the trainer. Done: pinnrl.native and build_trainer(derivatives="native"), 10.6 → 5.4 ms a step on the benchmark problem with the same gradients to rounding; opt-in; macOS, plain tanh networks, first and pure second derivatives.
    • Layer normalization in the kernel, so the packaged default network benefits (I12). Done: 32 → 10.4 ms a step on the default network. The check against autograd exposed a PyTorch defect, a wrong third-order derivative of nn.LayerNorm (weight gradients of second-order residuals 2–3 % off); the package's networks now use ExactLayerNorm.
    • Mixed and third- and fourth-order derivatives (KdV, Cahn–Hilliard) (I13). Done: the kernel carries general Taylor coefficients through tanh and layer normalization; residual, loss and weight gradient agree with autograd to rounding on heat, KdV, a mixed \(u_{xxt}\), the beam and Cahn–Hilliard, and the step gains 1.9–4× on the plain network and 3–7× with layer normalization, the more the higher the order; the special cases of I11/I12 lose under 5 %.
    • A Linux build on OpenBLAS, tested in CI (I14). Done: the same source builds with g++ -lopenblas on first use, with a vectorised tanh of its own; CI installs OpenBLAS and fails rather than skips the kernel tests. On the same machine the Linux step gains 1.4–3.0× against 1.9–4.7× under Accelerate: Taylor mode saves the elementwise work, not the matrix products, and without Apple's AMX those are two thirds of the step.
    • One value pass for boundary and initial points; the registry's PDE classes through the kernel (I15). Done: every face and the initial points share one kernel call (worth 2 % of the heat step), and PDEBase.compute_derivatives goes through the kernel for the registry's classes, which gain 1.7–2.7× on a plain network and 2.3–4.7× with layer normalization; pinnrl-train --derivatives native now applies to every problem.
    • Compiled right-hand sides for the method-of-lines reference solvers, which the classical estimators spend their time in (I16). Done: the evaporator's model under a compiled SDIRK4 integrator with exact per-cell stage solves (reference(method="native"), native_propagator, monitor_fouling(integrator="auto")); 3–8× per solve on smooth inputs, 50–100× on a plant record whose kinks collapse BDF, a batch fit from 106 s to 0.7 s with the same estimate; the monitor 1.6×, its time now in the filter's Jacobian and matrix exponential.
    • A process unit whose forward solve is not a cheap initial-value problem (a transient or counter-current dryer, a droplet size distribution, wall deposition): the first place the PINN twin's case can be tested, after three units on which the classical estimator through the reference solver won. Done: pinnrl.process.CounterCurrentDryer (J13), the air against the falling droplets: the steady state is a boundary-value problem solved by shooting (100 ms, twenty times the co-current tower) and the transient a hyperbolic system with characteristics both ways, which the method of lines with a sparse Jacobian integrates in 0.04–0.6 s. The PINN's case is not made: a fit of the curve's two parameters and the wall loss from one transient record takes 10 s and lands within the linear prediction, while the PINN twin fails the misfit test on every run (its forward solve, with the equations scaled and the residual weight tuned, stays at 12–15 % on the moisture). What it would take is a model with no method-of-lines form at all.
    • The line-level twin: a multi-pass evaporator feeding the dryer, with errors propagated across the units (J10). Done: pinnrl.process.ProcessLine chains evaporator passes into the dryer (the concentrate sets the droplets' solids and the solids flow) with steady, reference, records and propagate (the variance budget of the powder by source, linear and Monte Carlo). On a four-hour shift with three fouling passes, the powder inherits the feed flow and the droplet size once the fouling is monitored, but propagation is the wrong estimator for it: the dryer's own records determine the powder to ±0.005 against ±0.09 by propagation (±0.001 with every record), information flows downstream only (the dryer's records leave the fouling at its prior), and the first pass's fouling is one unknown with the feed's calibration; ten simulated shifts confirm the linear predictions.

    v0.7: process twins (released 2026-11-12)¶

    • pinnrl.process: the falling-film evaporator with its method-of-lines reference simulator and custom_pde() form (J01, J02 done); fouling estimation from outlet sensors (J03: the drift to 9–16 %, at the surrogate's limit) and its identifiability (J04: the data allow 5 % on the end value; U and the constant fouling are one unknown; the steam temperature is the nuisance that matters). The drying droplet (pinnrl.process.DryingDroplet, J07) is the second unit: its forward PINN solve reaches 8–14 %; the free-function closure collapses to a constant from a cold start and reaches 1.7–2.1 % from a pointwise estimate of the record (J07b), with a 1-in-3 risk of leaving the basin. The intervals are measured (J06, 100 data sets): a batch fit through the reference solver and a trend filter on 51 cells are calibrated (0.91–0.99) where the model is right and the fouling's assumed form contains the truth; an 11-cell model, a ramp assumed for a curve that bends, or a steam record trusted beyond its accuracy each break it, and the PINN twin fails to train on 22 of 36 runs and has no calibrated interval. A learned closure is checked by DryingDroplet.record_misfit through the reference solver (J07c catches every failure of J07b), and a monotone closure fitted by shooting reaches 1.5 % from a cold start on every seed (J07d): on the two units built so far the classical estimators win, and the PINN's case is a model without a cheap trusted forward solve. UnknownFunction(anchor=...) holds a value at a point (J07e: the closure zero at equilibrium by construction removes the pointwise start's 60–90-fold misfit, and the PINN refinement then adds nothing), and pde.sensor_misfit with train_with_restarts is the acceptance test and restart rule a twin applies to itself. The dryer-scale model is pinnrl.process.SprayDryer, the droplet coupled to its air in a co-current tower (J11): one solve takes 5 ms, so the estimator is again a fit through the reference; a tower's instruments determine the two parameters of a known curve form (±0.03 from five operating points) and 4–6 of a free-form closure's 11 directions, yet predict the powder moisture outside the campaign to 1–2 %. Open: a tower whose forward solve is not a cheap initial-value problem (transient, counter-current, a size distribution, wall deposition), where the PINN's case can first be tested. The stickiness margin is SprayDryer.stickiness_margin (J08): the twin gives it at the outlet to 1.0–1.5 K where a lab assay gives 1.6–3.2 K and the air's water balance 23–59 K. K09 (linearized stability) is done: the physics is convectively stabilised and not stiff; the discretised operator's spectrum is a pseudospectrum.
    • Classical estimators on the same models: pinnrl.process.ExtendedKalmanFilter with an RTS smoother and FallingFilmEvaporator.fouling_state_space (J05: on a known model the filter beats the PINN twin by a wide margin at a thousandth of the cost; the PINN's case is the partly unknown model). pinnrl.process.MovingHorizonEstimator adds bounds on states and disturbances (J05b: the filter's accuracy on the evaporator at 10–35 times the cost; the growth constraint smooths without correcting). augment_local_linear_trend, time_to_threshold and monitor_fouling are the drift model, the time to the next cleaning and the packaged fouling monitor J06 arrives at.
    • Historian adapter: CSV or Parquet plus a tag map to sensor definitions. Done: pinnrl.process.Historian (wide and long exports, quality flags, dated timestamps, unit conversion, windows and resampling) and Historian.apply(tag_map), which gives the inputs as TimeSeries, the sensors with their records, and records() for the filters; see Process twins.
    • A dashboard "Process" view: soft-sensor trends with uncertainty bands, and time to the next cleaning. Done: the Process tab runs monitor_fouling on an export and a tag map and plots the fouling with its band, the projected cleaning time with its interval and the outlet records against the model; see Dashboard.
    • Bayesian measurement design for sensors and lab sampling (J09; P24). Done: pinnrl.analysis.posterior_covariance, target_std, information_gain and greedy_design; on the evaporator with every instrument error admitted, the steam offset and the four mass-balance instruments jointly limit the fouling estimate (10.6 %), no single calibration pays, a condensate meter halves it and with a 4 K steam swing reaches 2.8 %; lab samples buy little and are best at the end, a quarter and past the middle of the window. See Benchmarks.
    • Type checking (mypy) across the package. Done: uv run mypy passes on the 66 modules of pinnrl (default strictness, configured in pyproject.toml) and runs in CI next to ruff.

    v0.6: richer unknowns and inputs (released 2026-11-04)¶

    • Field-valued unknowns: a learnable coefficient field \(\alpha(x, t)\) or closure \(f(u)\), with positivity and monotonicity constraints. Done: CustomPDE(unknown_functions=...) with UnknownFunction; F09 recovers \(\alpha(t)\) to 4 % and a two-layer \(\alpha(x)\) in shape on heat, and shows which fields the data cannot determine.
    • Coupled multi-field systems (output_dim > 1) with per-field BCs and loss weights. Done: CustomPDE(boundary_conditions={field: ...}, field_weights=...); the catalogue's reaction_diffusion_pair trains to its closed form in test_coupled_systems.py.
    • Measured inputs: BCs and forcing from interpolated time series. Done: CustomPDE(inputs={"q": {"path": "left.csv"}}, boundary_conditions={"dirichlet": {"left": "q"}}); test_measured_inputs.py trains heat with its boundary following a CSV.
    • Sensor operators: point, boundary and integral observations with per-sensor noise and delay. Done: CustomPDE(sensors=[PointSensor, BoundarySensor, IntegralSensor]), pde.observe, sensor_jacobian; K02 ranks layouts by their Fisher information and trains on sensor records (F05's fixed probes are one PointSensor each; its results predate the module).
    • Non-dimensionalization helpers (a reference scale per variable). Done: CustomPDE(scales=...) + build_trainer(normalize=True) / --normalize; a heat problem in millimetres, seconds and kelvin trains like the unit problem (test_normalization.py). J01 will be the first process model to use it.
    • High-dimensional stability: dimension sweeps of stability constants and quadrature error. Done: K08, heat and convection in \(d = 1 \ldots 5\); the quadrature gap is dimension-independent, the stability constant grows with the condition errors, and high-dimensional convection collapses to zero.

    v0.5: the inverse-modelling core (released 2026-10-26)¶

    The goal is to estimate unknown physics with known validity conditions and calibrated uncertainty. Diagnostics come before UQ methods, because an unidentifiable or ill-conditioned problem has no meaningful error bar.

    1. User-defined equations. CustomPDE: any PDE, ODE, steady problem or system from its residual as text (SymPy-parsed, autograd derivatives) or a Python callable, with expression-valued initial and exact solutions, identifiable parameters, and pinnrl-train --pde-file. Every later module (diagnostics, UQ, the process models of v0.7) is written against it rather than against one class per equation. Done: test_custom_pde.py checks parity with the shipped Heat, Burgers and pendulum residuals; see Custom equations.
    2. Theory pages. Well-posedness and conditional stability; structural vs practical identifiability; the Bayesian view (loss = negative log-posterior, data weight = 1/σ²); sources of uncertainty; calibration; the numerical-analysis bridge (Lax equivalence, stability constants, PINN error estimates). Done: Theory, four pages cited by DOI; the maintainer's reference papers are still to be added. Every later module cites the condition it relies on.
    3. Identification baseline. Scalar parameters vs noise, sensors, initial guess and data weight. Done: F01–F05 in experiments/ and Benchmarks. The surrogate floor is 2 % (heat), 20 % (KdV soliton) and 150 % (Burgers shock); above it the estimator is near-efficient. The data-weight question is K39.
    4. pinnrl.analysis: conditioning diagnostics. The sensitivity Jacobian by the implicit-function theorem on the trained surrogate; Fisher information, Cramér–Rao bound, correlations and eigen-directions; the loss-Hessian (Lanczos) and tangent-kernel spectra. Done: pinnrl.analysis; K01 (validated on heat and KdV, wrong on the unresolved Burgers shock), K03 and F07 are in experiments/. Profile likelihood is a driver (F07), not yet an API.
    5. Disturbance and stability analysis. Perturbation suites for data and for the problem; the linear prediction of the estimate's shift; empirical stability constants. Done: pinnrl.analysis.disturbance; K05 (bias and delay shifts match \(F^{-1}J^\top\Sigma^{-1}\delta y\) to 20 %), K06 (the surrogate respects the equation's stability above its own field error) and K07 (\(C \approx 1\) for linear evolution equations; the beam's error is set by its boundary terms) are in experiments/.
    6. pinnrl.uq: calibrated uncertainty. A likelihood-based data term (σ sets the weight and the misfit tolerance); deep ensembles with a dispersion diagnostic; a Laplace approximation that reuses the Hessian machinery of pinnrl.analysis; the region of equivalence as the primary output, sampled by a cloud particle swarm over the parameters on a parametric surrogate \(u_w(x, t; \theta)\), with intervals, percentiles and CDFs by counting (theory); coverage, width and CRPS metrics. Done: pinnrl.uq; F06/K10 (the Laplace width is exact for the random error, the 2 % bias costs coverage, ensembles over seeds cover 13 %, the physics region 90 %), K39 (the noise-model weight is worse than the tuned one because the surrogate's error is systematic) and K46 (the swarm confirms the ellipse at these noise levels and under-samples its edges) are in experiments/. K47 (the weighted swarm is centred but 0.5–0.7 as wide as the posterior) and K45 (one parametric surrogate covers the prior range to 0.2–2 % and the swarm on its misfit reproduces the closed-form region) complete the item.
    7. Sampling follow-ups for P02. B02 (more PDEs), B03 (the RAD k, c grid), B04 (resampling frequency), B08 (point-count scaling). Done: no sampler beats uniform significantly on smooth problems; the resampling cadence changes the Burgers error threefold and the study default moves to 10 steps; good RAD settings lie on c ≈ k/2 and a zero floor with a sharp exponent fails; the error scales as N^−1/3 on Burgers and not at all on Allen–Cahn. P02 can be drafted.

    v0.4: clean, verified, documented (released 2026-10-24)¶

    • Physics audit: every exact solution satisfies its PDE, IC and BC; real Dirichlet, Neumann and periodic BCs; correct 2-D derivatives. Done: test_physics_consistency.py is green.
    • One training loop (PDETrainer.train / train_steps), one PDE registry, one entry point per action.
    • A working, experimental RL bandit sampler; RAD with k/c.
    • Numerical reference solutions. Done: Burgers reproduces Basdevant et al. (1986), \(u_x(0, 1.6037/\pi) = -152.00516\) for \(\nu = 0.01/\pi\); the Allen–Cahn solution is grid-converged.
    • B01/B06 sampling benchmark, 10 seeds at equal steps and equal evaluations. Done: Benchmarks, experiments/B01_sampling_equal_compute/.
    • Docs rewritten and audited against the code; ruff with docstring linting; strict docs build.
    • Bug batch from the documentation audit (Well loader coordinates, LRW zero-gradient weighting, network defaults, dashboard plots). Done: each fix has a test that fails without it (test_audit_regressions.py, test_well_loader.py).
    • Release. Done: CI and scripts/verify_release.sh are green, and v0.4.0 is on PyPI via trusted publishing.
